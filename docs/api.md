# API и модель данных

## Типы вопросов

| Тип | Что выбирает зритель | Примеры |
|---|---|---|
| `single` | Ровно один вариант | А/Б, «да / нет», шкала с вариантами от админа |
| `multi` | Один или несколько вариантов | «Что из этого вы смотрите?» |

Вариантов не больше 64: столько помещается в битовую маску записи. Сколько показывать на экране, решает продукт. Для ТВ разумно 2–4.

## Жизненный цикл опроса

```
draft ──activate──► active ──конец окна + допуск──► counting ──► final
  ▲                    │
  └──cancel (до окна)──┘
```

- `draft`: опрос можно редактировать.
- `active`: конфиг опубликован на CDN, приём принимает голоса в окне. Менять опрос нельзя; до начала окна запуск можно отменить (`cancel`).
- `counting`: окно закрыто, идут этап 1 и этап 2.
- `final`: итог окончательный.

## Публичный API

Страница и API на одном домене, CDN проксирует `/api`.

**`GET /p/{poll_id}`** — страница опроса (статика).

**`GET /p/{poll_id}/config.json`** — вопрос, тип, варианты, окно (статика, публикуется при активации).

**`POST /api/vote`**

```json
{
  "poll_id": "3f6c…",
  "options": [2],
  "voter_id": "b1e0…",
  "fp": { "…": "компоненты отпечатка" }
}
```

| Ответ | Когда |
|---|---|
| `204` | Голос записан в Kafka. Ответ одинаковый и для первого голоса, и для повтора: дедупликация идёт позже и наружу не видна. |
| `400` | Тело не разбирается: не JSON, нет полей, неверные типы (`fp` не объект, `options` не список целых чисел — `"0"`, `true`, `0.0` тоже неверны), `poll_id` или `voter_id` не UUID. |
| `404` | Опрос не найден или в `draft`. |
| `410` | Опрос не в `draft`, но время вне окна (до начала, после конца + допуск, в том числе в `counting` и `final`). Опрос, закрытый больше суток назад, приём уже не помнит — `404`. |
| `422` | Неверные варианты: пусто, вне списка, повтор, несколько у `single`. |
| `503` | Приём перегружен, клиент повторяет с задержкой. |

Любой другой `5xx` и обрыв связи (например, `530` от Cloudflare, когда туннель закрыт) страница тоже повторяет с задержкой и пишет «Нет связи с сервером голосования». Повторяет, пока голосование может идти: до `window_end + grace_s` из `config.json` плюс 10 с на расхождение часов, но не меньше 15 с. Потом пишет «Голос не отправлен» и снова даёт нажать «Голосовать».

Хэш отпечатка считает узел приёма, а не клиент: так формат и состав отпечатка под нашим контролем.

## Админка

Все запросы с заголовком `Authorization: Bearer <токен>`, иначе `401`.

Тело `POST /admin/polls` (время — ISO 8601 с часовым поясом, `Z` или `+03:00`; без пояса — `422`):

```json
{ "question": "Какой напиток утром?", "type": "single", "options": ["Кофе", "Чай"],
  "window_start": "2026-10-01T18:00:00Z", "window_end": "2026-10-01T18:01:00Z", "grace_s": 60 }
```

- Вопрос и каждый вариант не пустые (строка из одних пробелов считается пустой), вариантов 2–64, `window_end > window_start`, `0 ≤ grace_s ≤ 86400`, иначе `422`.
- Ответ — объект опроса: те же поля плюс `id`, `status`, `created_at`, `options: [{idx, label}]`. Создание — `201`.
- `PATCH` принимает любое подмножество тех же полей. `PATCH` и `activate` не в `draft` — `409`. `activate`, когда окно уже прошло, — `409`.
- `GET /admin/polls` — массив объектов опроса, новые сверху. `GET /admin/polls/{id}` — один опрос.
- Неизвестный или некорректный `id` (не UUID) на любом запросе админки — `404`. Ошибки `422` у `POST` и `PATCH` — в одном формате (список `detail`, как у FastAPI). `PATCH` с невалидными полями — `422`, по тем же правилам, что и `POST`.
- Окно «уже прошло» для `activate` — это `now > window_end + grace_s`.
- `DELETE` — `204`; можно только в `draft` и `final` (во время эфира и подсчёта — `409`). Удаляются опрос и все его строки в Postgres, а также опубликованный `config.json`; после этого `config.json` и голос отвечают `404`, а страница показывает «Опрос не найден». Сырые голоса в Kafka удаляются по сроку хранения.
- `GET /admin/public-url` → `{"tunnel": "https://….trycloudflare.com" | null, "lan": "http://192.168.1.12:8090" | null}`. `tunnel` не `null`, только пока туннель открыт. Ссылка и QR для зрителей строятся от `tunnel`, если он есть, иначе от `lan`, иначе от `http://localhost:8090` (зрительский вход).
- `POST /admin/tunnel` открывает страницу голосования в интернет (Cloudflare quick tunnel на зрительский вход; админка остаётся только на этом компьютере). Ждёт, пока туннель поднимется, и отвечает как `public-url`; не поднялся за 30 с — `503`. Повторный вызов при открытом туннеле ничего не меняет. `DELETE /admin/tunnel` закрывает его, `204`. Запуск опроса туннель не открывает: это отдельный запрос.
- Редактирование (`PATCH`) — только в `draft`: после активации конфиг уже у зрителей.
- `cancel` — только в `active` до начала окна (`now < window_start`), иначе `409`. Опрос снова `draft`, соль стирается, `config.json` снимается с публикации: страница показывает «Опрос не найден», голос — `404`. Голосов до окна не бывает, поэтому терять нечего. Ответ — объект опроса.
- `finish` — только в `active` и пока `window_start < now < window_end`, иначе `409`. Ставит `window_end = now`, `grace_s` не меняется: зрители с отстающей трансляцией ещё успевают проголосовать. Дальше обычный подсчёт. Ответ — объект опроса.

| Запрос | Что делает |
|---|---|
| `POST /admin/polls` | Создать опрос (`draft`): вопрос, тип, варианты, начало и конец окна, допуск. |
| `PATCH /admin/polls/{id}` | Изменить опрос, только в `draft`. |
| `POST /admin/polls/{id}/activate` | Перевести в `active`, опубликовать конфиг. |
| `POST /admin/polls/{id}/finish` | Завершить досрочно. |
| `POST /admin/polls/{id}/cancel` | Отменить запуск запланированного опроса: снова `draft`. |
| `DELETE /admin/polls/{id}` | Удалить опрос. |
| `GET /admin/polls` | Список опросов. |
| `GET /admin/public-url` | Адреса, по которым стенд виден с телефона. |
| `GET /admin/timezone` | Часовой пояс компьютера со стендом: `{"timezone": "Europe/Moscow" \| null}`. |
| `POST /admin/tunnel`, `DELETE /admin/tunnel` | Открыть и закрыть страницу голосования из интернета. |
| `GET /admin/polls/{id}` | Опрос. |
| `GET /admin/polls/{id}/results` | Итоги. |
| `GET /admin/polls/{id}/analytics` | Аналитика. |

Итоги до `final` — только `{status, received}`, без распределения по вариантам. В `final` — полный ответ:

```json
{
  "status": "final",
  "received": 25300000,
  "total": 25000000,
  "counted": 24100000,
  "over_limit_share": 0.036,
  "options": [
    { "idx": 0, "label": "Да",  "counted": 15000000, "total": 15600000, "share": 0.622 },
    { "idx": 1, "label": "Нет", "counted": 9100000,  "total": 9400000,  "share": 0.378 }
  ]
}
```

- `received` — все пришедшие голоса; `total` — после «один голос на `voter_id`»; `counted` — засчитанные после лимитов. Точные определения — в [contracts.md](contracts.md).
- `share` = `counted` варианта / `counted` в корне; у `multi` сумма долей может быть больше 1. При нуле голосов `share` и `over_limit_share` — `null`.

### Аналитика

Только агрегаты. `timeline` и `model` доступны и во время эфира (число голосов без распределения по вариантам), `funnel` и `ip_concentration` — в `final`, до этого `null`.

```json
{
  "status": "final",
  "window_start": "2026-10-01T18:00:00+00:00",
  "timeline": [ { "t": 0, "received": 120 }, { "t": 1, "received": 450 } ],
  "model": { "median_s": 14, "sigma": 0.5 },
  "funnel": { "received": 25300000, "unique_voters": 25000000, "counted": 24100000,
              "rejected": { "repeat_voter": 300000, "key_limit": 850000, "ip_ceiling": 50000 } },
  "ip_concentration": [ { "bucket": "1",      "ips": 18000000, "votes": 18000000 },
                        { "bucket": "2-10",   "ips": 2000000,  "votes": 5000000 },
                        { "bucket": "11-100", "ips": 20000,    "votes": 1500000 },
                        { "bucket": "101+",   "ips": 1000,     "votes": 500000 } ]
}
```

- `timeline`: число пришедших голосов по секундам от `window_start` (по времени приёма), без пропусков от 0 до последней секунды с голосами.
- `model`: параметры логнормальной модели из [architecture.md](architecture.md), чтобы админка нарисовала её поверх `timeline`.
- `funnel`: `unique_voters` — после этапа 1; `rejected` — сколько отсеяно на каждом шаге. Голос сверх обоих лимитов считается в `key_limit`: он проверяется первым.
- `ip_concentration`: сколько IP (по `ip_hmac`) дали голосов в каждом диапазоне, считая голоса после этапа 1. Всегда 4 диапазона, пустые — с нулями.
- Без голосов `timeline` — `[]`. В `draft` ответ того же вида: `timeline` пустой, `funnel` и `ip_concentration` — `null`.

## Postgres

```
polls          (id uuid PK, question, type, status, window_start, window_end, grace_s,
                salt bytea NULL, created_at)
options        (poll_id, idx smallint, label,                       PK (poll_id, idx))
results        (poll_id, partition, option_idx, counted, total, last_offset,
                                                                    PK (poll_id, partition, option_idx))
stage_progress (poll_id, stage, partition, votes, end_offset, done_at,
                                                                    PK (poll_id, stage, partition))
fp_counts      (poll_id, partition, blob bytea,                     PK (poll_id, partition))
timeline       (poll_id, partition, second, votes,                  PK (poll_id, partition, second))
stage2_stats   (poll_id, partition, key_limit, ip_ceiling, ip_hist jsonb, last_offset,
                                                                    PK (poll_id, partition))
```

- `salt` — секретная соль для `HMAC(IP)`. Обнуляется после закрытия окна.
- `results` обновляется, только если `last_offset` больше сохранённого.
- `results`: строка с `option_idx = -1` хранит число голосов партиции (корневые `counted` и `total`): у `multi` сумма по вариантам не равна числу голосов.
- `fp_counts` — блоки `c(f)` для слияния между проходами этапа 2.
- `timeline` пишет этап 1: абсолютные значения, пересчитываются при рестарте.
- `stage2_stats` пишет этап 2 по правилу `last_offset`: отсеянные по лимиту ключа и потолку IP, гистограмма IP по диапазонам.

## Запись в Kafka

Бинарная, фиксированного размера. Числа — little-endian, UUID — 16 байт в порядке RFC 4122 (`uuid.bytes`):

| Поле | Байт | |
|---|---|---|
| `version` | 1 | Версия формата, сейчас 1 |
| `poll_id` | 16 | UUID |
| `options` | 8 | Битовая маска вариантов |
| `received_at` | 8 | Время приёма, мс |
| `ip_hmac` | 16 | HMAC-SHA256(IP или префикс `/64`, соль опроса), первые 16 байт |
| `fp_hash` | 8 | Хэш стабильных компонентов отпечатка |
| `voter_id` | 16 | UUID |

Итого 73 Б, с накладными расходами Kafka ≈ 100 Б. JSON занял бы ~300 Б.

Топики:
- `votes_raw` — ключ `voter_id`, туда пишет приём;
- `votes_by_ip` — ключ `ip_hmac`, туда пишет этап 1.

Число партиций фиксируется до опроса.
