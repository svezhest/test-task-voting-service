# Дедупликация голосов

## Условия

- Голосование анонимное, без регистрации, аудитория ≈ 100M. Окно голосования — ролик плюс допуск на задержку вещания.
- Защищаемся от обычного пользователя. **Он умеет открыть инкогнито и включить или переключить VPN.**
- **Решение автора (в спецификации его нет):** голоса через VPN и с IP дата-центров принимаем. Там, где сервис заблокирован, до него доберутся только через VPN. В режиме белых списков в России VPN выходит через разрешённые российские облака, поэтому тысячи людей оказываются за немногими IP.
- От браузера засчитывается **первый** голос.

## Коротко

1. **Один голос на `voter_id`.** Первый этап, потоковый, по всему опросу.
2. **Лимит на ключ «отпечаток + IP».** Второй этап, после окна, в два прохода. Лимит считается из того, насколько отпечаток частый и сколько людей сидит за IP.
3. **Потолок на IP:** 5000 голосов в минуту.

Голоса сверх лимита **сохраняются с пометкой, но в итог не входят**: они нужны для статистики.

## Признаки

| Признак | Что даёт | Ограничение |
|---|---|---|
| `voter_id` (cookie + localStorage) | Один голос на браузер, где бы он ни был: смена Wi-Fi на LTE или VPN-сервера не помогает | Обнуляется в инкогнито и в другом браузере |
| IP | Показывает, где сидят люди | Один на многих (мобильный CGNAT, VPN, публичный Wi-Fi), легко меняется |
| Отпечаток браузера (свой) | Стабильные признаки не меняются в инкогнито и при смене VPN | У одинаковых устройств одинаковый |

**Отпечаток — единый белый список признаков, которые ни один браузер не шумит и которые не меняются между обычным и приватным окном**: модель (если браузер её отдаёт), DPR и цвет экрана, первый язык, локаль, часовой пояс, пользовательские настройки. Отпечаток намеренно грубый. Подробности — в [fingerprint.md](fingerprint.md).

Отпечаток и IP работают только вместе. Отпечаток без IP склеил бы одинаковые устройства по всему миру. IP в ключе нужен для того, чтобы совпадения оставались в пределах одного адреса.

## Этап 1: один голос на `voter_id`

Топик разбит по `voter_id`. Засчитывается первый голос каждого `voter_id` в порядке партиции, повторы уходят с пометкой. Результат зависит только от содержимого партиции.

## Этап 2: лимит на ключ «отпечаток + IP»

Считается после закрытия окна по каждой партиции `votes_by_ip` (партиции разбиты по `HMAC(IP)`), в два прохода.

**Первый проход — статистика:**
- `c(f)`: число разных `voter_id` с отпечатком `f`. После прохода эти счётчики один раз сливаются по всем партициям, и из них получается `p(f) = c(f) / Σ c`. Слияние выполняется однократно, это не горячий ключ.
- `D(IP)`: число разных отпечатков с IP.
- `V(ключ)`: число разных `voter_id` на ключе.

**Второй проход — решения.** На каждом ключе в порядке партиции засчитываем первые `L` голосов:

```
L = max(N, V(ключ) − R)
```

Решения зависят только от содержимого партиций, поэтому пересчёт после сбоя даёт тот же итог.

### Почему `p(f)` считается по `voter_id`

`p(f)` не считается по голосам: иначе накрутчик сделал бы свой отпечаток «частым» и поднял бы себе лимит. Повторы из того же браузера отсеяны на этапе 1, а из инкогнито накрутчик добавит не больше `R` на ключ. На фоне миллионов это ничего не меняет.

### Люди за IP `n(IP)`

`n̂` — решение уравнения

```
D = Σ_f (1 − (1 − p(f))^n̂)
```

Функция монотонна, поэтому корень ищем бисекцией. Чтобы не суммировать по сотням тысяч отпечатков, `p` сворачиваем в гистограмму из ~200 логарифмических корзин. `n̂` считается один раз на IP.

### Лимит `N`

Число честных людей с отпечатком `f` за этим IP приближённо ~ Пуассон(λ), где `λ = n̂ · p(f)`:

```
N = 1 + Q_Poisson(λ; 0.9999)
```

`Q` берём из заранее посчитанной таблицы по сетке `λ`.

| Людей за IP | p = 2% | p = 0.1% | p = 0.01% |
|---|---|---|---|
| 3 (дом) | 3 | 2 | 2 |
| 50 | 7 | 3 | 2 |
| 1000 (метро) | 40 | 7 | 4 |
| 3000 | 92 | 12 | 5 |

При точных `λ` в лимит упирается ~10⁻⁴ честных голосующих, то есть ~1000 на 10M. Мы работаем с оценками `p` и `n̂`, поэтому реальная доля выше: 10⁻⁴ — оценка снизу.

### Поправка `R`: одинаковые устройства за одним NAT

300 одинаковых iPad в школе дают `D = 1`, оценка решает, что за IP один человек, и `N = 2`. Спасает время. Обычный накрутчик открывает новое окно инкогнито примерно раз в 5 с, значит, за окно голосования он создаёт не больше

```
R = длительность окна / 5 с
```

разных `voter_id` на ключ. Для окна в 60 с `R ≈ 12`. Всё, что на ключе сверх `R` разных `voter_id`, — точно другие люди.

| Кто за ключом | Разных `voter_id` | Лимит `L` |
|---|---|---|
| Один накрутчик | ≤ R | `N` |
| Семья, 3 одинаковых айфона | 3 | `N = 3` |
| 300 одинаковых iPad | 300 | 300 − 12 = 288 |

### Потолок на IP: 5000 в минуту

Прикидка, сколько людей физически помещается за одним IPv4-адресом (IPv6 считаем по префиксу `/64`):
- **Мобильный CGNAT** даёт абоненту блок из 256–4096 портов, это не больше ~256 абонентов на адрес. Бывают блоки по 64–128 портов, тогда до ~1000.
- **NAT без блоков** (VPN, публичный Wi-Fi): 65 535 портов / 20–50 соединений на телефон ≈ 1300–3300 устройств.

5000 взято с запасом. Число соединений на телефон — допущение: если их меньше, за адресом помещается больше устройств, и потолок нужно поднять. Потолок — единственное, что останавливает скрипт с бесконечными `voter_id`.

## Пределы защиты

Точной дедупликации без входа при инкогнито и VPN не бывает. Схема **ограничивает** повторы, а не исключает их.

| Способ повтора | Цена | Результат |
|---|---|---|
| Тот же браузер, другая сеть (Wi-Fi → LTE, другой VPN-сервер) | — | Отсекается на этапе 1 |
| Новое окно инкогнито | ≈ 5 с | Засчитывается, пока у ключа есть запас: `L − 1 − λ`, не больше `R` |
| Инкогнито + смена VPN-сервера | ≈ 15–20 с | Новый ключ со своим запасом |

Итог: не больше ~`R` лишних голосов на человека за окно, в обычном домашнем случае 1–2.

**Известные ограничения:**
- смена темы, размера шрифта или настроек доступности даёт новый отпечаток; для обычного пользователя это неочевидно, а без этих настроек отпечаток был бы грубее;
- другой браузер на том же телефоне (Safari, затем Chrome или встроенный браузер Telegram) — это другие cookie и другой отпечаток, то есть +1–2 голоса по числу браузеров;
- скрипт с бесконечными `voter_id` ограничен только потолком на IP; это уже не обычный пользователь;
- чем длиннее допуск на задержку вещания, тем больше `R`.

## Данные

- IP хешируется `HMAC` с секретной солью опроса прямо на приёме. Соль уничтожается после закрытия окна, дальше IP из хэша не восстановить.
- В Kafka данные хранятся несколько дней. Состояние потребителей удаляется после финального итога. В админке только агрегаты.
- Отпечаток браузера может требовать согласия пользователя (GDPR/ePrivacy, 152-ФЗ). Это вопрос к юристам до запуска.
- Метрики: доля голосов сверх лимита по опросу. Резкий рост значит, что лимиты откалиброваны неверно или идёт накрутка.
