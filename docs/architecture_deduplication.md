# Дедупликация голосов

## Условия и модель угроз

- Голосование анонимное, без регистрации. Окно ≈ 60 секунд, аудитория ≈ 100M человек по всему миру.
- От обхода защищаемся на уровне обычного пользователя, не программиста. **Обычный пользователь умеет открыть инкогнито и включить или переключить VPN.**
- **Решение автора (в спецификации его нет):** голоса через VPN и с IP дата-центров принимаем. В странах с блокировками сервис могут открыть только через VPN. При режиме белых списков в России VPN выходит через разрешённые российские облака, поэтому тысячи людей оказываются за немногими IP.
- Засчитывается **первый** голос.

## Какие признаки у нас есть

| Признак | Что даёт | Чем ограничен |
|---|---|---|
| Cookie + localStorage (`voter_id`) | Честный человек случайно не проголосует дважды | Обнуляется в инкогнито и в другом браузере |
| IP | Показывает, где сидят люди | Общий у многих (мобильный CGNAT, VPN, публичный Wi-Fi) и легко меняется |
| Отпечаток браузера (пишем сами) | Не меняется в инкогнито и при смене VPN | Одинаковые устройства дают одинаковый отпечаток |

Что входит в отпечаток:

- **Android и десктоп:**
  - модель (`navigator.userAgentData.getHighEntropyValues(["model"])`);
  - GPU (WebGL);
  - canvas;
  - экран, язык, часовой пояс, пользовательские настройки (`prefers-*`).
- **iOS 26 (Safari).** Часть признаков бесполезна:
  - версия ОС в User-Agent заморожена (`18_6`);
  - canvas, WebGL и WebAudio зашумлены отдельно для каждой сессии;
  - `hardwareConcurrency` случаен при каждом чтении.

  Остаются: класс модели по экрану, версия Safari, язык, часовой пояс, тёмная тема, размер шрифта и настройки доступности. Отсюда большие группы одинаковых отпечатков.

Одного отпечатка, без IP, мало: он склеил бы одинаковые устройства по всему миру. IP в ключе нужен не чтобы опознать человека, а чтобы совпадения оставались в пределах одного адреса.

## Схема

1. **Cookie `voter_id`:** один голос на браузер.
2. **Ключ «отпечаток + IP»:** не больше `N(f, IP)` голосов на ключ. `N` считается для каждого голоса (см. ниже).
3. **Потолок на IP:** 5000 голосов в минуту на IPv4-адрес, для IPv6 на префикс `/64`.

### Редкость отпечатка `p(f)`

`p(f)` — доля отпечатка `f` среди всех голосующих в мире.

- Считаем её сами по живому потоку голосов и по данным прошлых эфиров.
- В первые секунды первого эфира данных ещё нет, поэтому отпечаток считается массовым.
- Отдельного класса «редкий» нет: редкость — это просто маленькое `p(f)`.

### Сколько людей за IP: `n(IP)`

`n(IP)` оцениваем по числу **разных отпечатков** `D`, пришедших с IP, с поправкой на совпадения. `n̂` — это решение уравнения

```
D = Σ_f (1 − (1 − p(f))^n̂)
```

Накрутчик из инкогнито и через VPN не создаёт новых отпечатков, поэтому раздуть эту оценку он не может.

### Лимит `N` на ключ «отпечаток + IP»

Число честных людей с отпечатком `f` за этим IP приближённо распределено по Пуассону с параметром

```
λ = n(IP) · p(f)
N = 1 + Q_Poisson(λ; 0.9999)
```

Здесь `Q` — квантиль. Уровень 0.9999 означает, что честный человек упирается в лимит с вероятностью не больше 10⁻⁴.

| Людей за IP | p = 2% (массовый) | p = 0.1% | p = 0.01% (редкий) |
|---|---|---|---|
| 3 (дом) | 3 | 2 | 2 |
| 50 | 7 | 3 | 2 |
| 1000 (метро) | 40 | 7 | 4 |
| 3000 | 92 | 12 | 5 |

- Накрутчику остаётся примерно `N − 1 − λ` лишних голосов: дома 1–2, у массового отпечатка в метро около 20.
- `p = 2%` — это пример верхней оценки, а не измерение. Реальные `p(f)` дают данные.

### Потолок на IP: 5000 голосов в минуту

Это физический максимум людей за одним IPv4-адресом:

- **Мобильный CGNAT.** Обычно 16–128 абонентов на адрес, на каждого выделяется блок из 256–4096 портов. Значит, на один адрес приходится не больше ~256 абонентов.
- **NAT без блоков портов** (VPN, публичный Wi-Fi). 65 535 портов делим на 20–50 одновременных соединений одного телефона (это допущение) и получаем ≈ 1300–3300 устройств.

5000 — верхняя граница с запасом. Всё, что выше, не может быть людьми за одним NAT, значит, это скрипт.

### Весь мир, а не одна страна

Модель от страны не зависит. Доля iPhone (≈29% в мире, ≈60% в США и Японии) автоматически отражается в `p(f)`. Общие IP у iCloud Private Relay обрабатываются так же, как у VPN.

## Граница защиты

Без входа, при инкогнито и VPN, точной дедупликации не бывает. Схема **ограничивает** повторные голоса, а не исключает их. На каждый повтор нужно новое приватное окно и другой VPN-сервер, это ≈ 15–20 секунд. Значит, за 60 секунд эфира обычный человек добавит не больше 2–3 лишних голосов.

Что можно добавить дальше, за рамками задания:
- Private Access Tokens (Apple / Cloudflare);
- вход через внешний ID-провайдер.
