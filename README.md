# Тестовое задание: сервис голосования

Анонимное голосование для ТВ-опросов: ролик на ~100M зрителей, минута на голос, QR-код, дедупликация без регистрации. Бэкенд на Python, приём отделён от подсчёта через Kafka.

## Запуск

Нужны Docker и [uv](https://docs.astral.sh/uv/).

```bash
make up         # поднять стенд; в конце печатает ссылку на админку и ссылки для зрителей
make populate   # демо-опросы: черновики, запланированный, завершённые с голосами, идущий
make test       # модульные и сквозные тесты на поднятом стенде
make loadtest   # нагрузочный тест на поднятом стенде (~2 мин): приём на ядро, этап 1, время до итога
make down       # остановить и удалить данные
```

- **Админка:** `http://localhost:8091/manage/`, токен `dev-token` (свой: `ADMIN_TOKEN=… make up`). Открыта только на этом компьютере.
- **Зрители:** QR в карточке опроса. По умолчанию ведёт на Cloudflare-туннель, откроется с любого телефона. Запасной вариант — адрес в локальной сети.

## Главное

1. **Приём отделён от подсчёта.** Узлы приёма без состояния пишут голос в Kafka и отвечают `204` только после подтверждения. Итог считается после окна, потоково его считать не нужно: живые итоги мы не показываем (видимый лидер искажает опрос).
2. **Нагрузка — из модели, а не из воздуха.** Ориентир — QR-ролик Coinbase на Super Bowl: 20M заходов за минуту. Кривая голосов логнормальная, пик ~1.6M RPS при 25M голосов и ~6.5M RPS, если проголосуют все 100M. Время эфира известно, поэтому мощности поднимаются заранее, а не автомасштабированием.
3. **Дедупликация в два этапа.**
   - Один голос на браузер (`voter_id`) — по всему опросу, смена сети или VPN не помогает.
   - Лимит на пару «отпечаток + IP». Он не константа: для каждого ключа считаем, сколько честных людей с таким отпечатком может сидеть за этим IP (распределение Пуассона). Поправка `R` пропускает школу с 300 одинаковыми iPad, а потолок на IP ловит скрипты.
4. **Отпечаток — единый белый список.** Сначала исключали шумящие признаки для каждого браузера, но исключения расползались на всех. Живой телефон с Cromite это подтвердил. Теперь в отпечатке только то, что ни один браузер не меняет между обычным окном и инкогнито.
5. **Честные границы.** Точной дедупликации без входа при инкогнито и VPN не бывает. Схема не исключает повторы, а ограничивает их (~5 с на повтор, минута эфира) и честно показывает отсев в админке.
6. **Итог детерминирован.** Состояние хранится на партицию, решения зависят только от её содержимого, запись итогов идёт по `last_offset`. Рестарт любого этапа даёт тот же итог до голоса.
7. **Приватность.** IP хешируется HMAC с солью опроса прямо на приёме, соль уничтожается после окна. В админке только агрегаты.

## Замеры

`make loadtest` на ноутбуке (Apple M1 Max, Docker Desktop, arm64): приём — 7 000–8 350 голосов/с на ядро, линейно на 1/2/4 репликах, 100 % `204`; этап 1 — 54 000 голосов/с на процесс; итог по 0.94M голосов — через 17 с после закрытия окна. Пересчёт на 1.6M и 6.5M RPS — экстраполяция, см. [architecture.md](docs/architecture.md#мощности).

## Как это сделано с ИИ

- Решения принимались в обсуждении и сначала фиксировались в `docs/`. Код писали агенты строго по контрактам ([CLAUDE.md](CLAUDE.md)): минимум кода, заглушки помечены `STUB`, неясное — вопросом, а не догадкой.
- Тесты писал отдельный агент, который не видел реализацию, только документы. 200+ тестов, включая сквозные сценарии накрутки.
- Код прошёл несколько раундов ревью агентами со свежим контекстом; каждый коммит с `Co-Authored-By`.
